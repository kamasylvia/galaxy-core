## 3. 当前维护重点

### 3.1 已采用的新规则

- `handle_kline_command()` 与 `KLineCommandService.get_kline()` 在 `start` 缺失时，都会先根据 symbol 推导默认开始日期。
- 默认开始日期来源于 AmazingData 开发手册 `2.2 数据详情` 中的数据起点说明。
- 股票 / 指数 / 债券 / 场内基金默认从 `20130101` 开始。
- 期权默认从 `20150101` 开始。
- 港股通默认从 `20230101` 开始。
- 期货按交易所分别使用文档中的起始月份首日。
- 当一次请求包含多个 symbol 时，统一使用各 symbol 默认起点中的最大值，避免无意义地请求不支持的更早历史区间。

### 3.2 当前维护边界

- `validate_start_end_by_period()` 仍只负责按周期裁剪日期精度，不承担证券类型推断职责。
- `get_valid_symbols_from_input()` 继续只负责 `SecurityType` 展开与代码筛选，不承载默认起始日期规则。
- 若后续调整默认起点，应优先修改时间工具层中的单一映射与 helper，避免在命令层重复写分支。
- `boards/` 目录现在是任务文档主入口，不再继续维护 `tasks/` 路径别名。

### 3.3 当前验证要求

- 目标测试集应至少覆盖：
  - `tests/kline/test_kline_command.py`
  - `tests/unit/test_kline_default_start_dates.py`
- 需要确认：
  - `start=None` 时不同证券类型的默认起点正确。
  - 混合 symbol 的“最大默认起点”规则正确。
  - `boards/` 目录迁移后，仓库内引用与本地设置路径一致。

## 5. 当前主要风险

### 风险 1：默认起点规则再次分叉

- 如果命令层之外再次引入单独的“缺省起始时间”逻辑，容易导致 CLI、兼容入口、同步层口径不一致。

### 风险 2：混合 symbol 语义被误改

- 当前规则是“使用最大默认起点”，不是“按每个 symbol 单独时间窗口查询”。
- 若后续改成逐 symbol 独立窗口，需要同步调整完整性检查与同步编排。

### 风险 3：目录迁移后残留旧引用

- `boards/` 已成为新目录名；若残留 `tasks/...` 路径，会影响文档互链与本地工具配置。
